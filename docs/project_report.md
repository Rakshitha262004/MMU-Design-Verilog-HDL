
Project Report: Memory Management Unit (MMU) Design using Verilog HDL

1. Objective
To design, implement, and verify a synthesizable Memory Management Unit in Verilog HDL that performs virtual-to-physical address translation using a page table, with valid-bit checking for page-fault detection and read/write permission checking for protection-fault detection.
2. MMU Concept
An MMU sits between the CPU and main memory. Every memory access generated by software uses a virtual address; the MMU translates it into a physical address before the access reaches RAM. This indirection is what makes virtual memory, process isolation, and memory protection possible without software having to manage physical memory directly.
3. Virtual-to-Physical Address Translation
The 16-bit virtual address is split into two fields:

Page Number (bits [15:8]) — selects an entry in the page table
Page Offset (bits [7:0]) — byte position within the page, unchanged by translation

The page table entry for the selected page number supplies an 8-bit frame number, which replaces the page number to form the physical address: {frame_number, page_offset}.
4. Page Table Design
The page table is implemented as a 256-entry register array (page_table[0:255]), each entry 11 bits wide:
BitsField[10:3]Frame Number (8 bits)[2]Valid bit[1]Write permission[0]Read permission
Entries are loaded through a synchronous write port (pt_write_en, pt_write_index, etc.), modeling how an operating system would populate page table entries at runtime. On reset, all entries are cleared to zero (all pages invalid), matching real system behavior where unmapped memory cannot be accessed.
5. Valid Bit Logic
Before any translation is returned, the design checks the valid bit of the selected page table entry. If the bit is 0, the page has never been mapped (or has been unmapped), and the module asserts page_fault while withholding a physical address — exactly how a real MMU would trap into the OS fault handler.
6. Permission Logic
If the page is valid, the design checks the requested access_type (0 = read, 1 = write) against the entry's read/write permission bits. A read request on a non-readable page, or a write request on a non-writable page, asserts protection_fault. This models hardware-enforced memory protection, e.g. preventing writes to a read-only code segment.
7. RTL Explanation
The design (rtl/mmu.v) is parameterized (address widths, offset width) and split into:

A synchronous block that initializes/programs the page table
Combinational logic that extracts page number/offset from the virtual address
A combinational output block implementing fault-priority logic: page fault is checked first, then protection fault, then successful translation — mirroring the order a real MMU evaluates these conditions.

8. Testbench Explanation
The testbench (tb/mmu_tb.v) uses two reusable tasks:

load_entry — programs a page table entry
check_translation — applies a virtual address and access type, then self-checks all four outputs against expected values

Eight test cases cover: valid read, valid write, a page fault on an unmapped page, a protection fault from writing to a read-only page, a valid read on that same read-only page, two boundary-address cases (highest page, min/max offset), and a disabled-request idle check.
9. Simulation Results
All 8 tests pass under Icarus Verilog simulation. Full console output is saved in simulation/simulation_log.txt; the waveform dump is in waveforms/mmu_waveform.vcd.
ALL 8 TESTS PASSED
10. Synthesis Considerations
The design uses only combinational logic and a synchronously-written register array — no clocked datapath beyond the page table memory itself — making it straightforward to synthesize on any FPGA toolchain (Vivado, Quartus) without timing closure concerns at typical FPGA clock speeds. The 256×11-bit page table maps efficiently to distributed RAM or block RAM depending on synthesis tool inference settings.
11. Conclusion
This project demonstrates, at the RTL level, the core mechanism that enables virtual memory and memory protection in real processors: address translation through a page table, gated by validity and permission checks. The design is fully simulation-verified, parameterized for reuse at other address widths, and accompanied by an FPGA constraints file for hardware deployment.
